## OpenVINO Release Management

The process described below outlines how OpenVINO releases are managed.

### Release Milestones

- Planning  
- Execution (development of new features)  
- Stabilization (Feature Freeze, Code Freeze milestones)  
- Validation  
- Distribution  

---

### Planning

This phase takes **2–4 weeks** and involves:
- Scoping the backlog  
- Prioritizing tasks  
- Analyzing requirements  
- Making commitments by developers based on timelines set by the release manager  

---

### Execution (Development of New Features)

- OpenVINO Contributing Guide  
- Code Contribution Guide  
- OpenVINO First Good Issue  

---

### Stabilization (Feature Freeze, Code Freeze)

- **Feature Freeze:**  
  No new features are added after this point. The team focuses on stabilizing existing features, fixing bugs, and improving performance.

- **Code Freeze:**  
  No new code changes are allowed except for critical bug fixes. This ensures stability and reduces the risk of introducing new issues.

---

### Release Validation

This is a continuous process executed regularly with different cadences:
- Nightly  
- Bi-weekly  
- Weekly  

After Code Freeze, final regression testing is performed to ensure:
- No new bugs are introduced  
- Software meets quality standards  

---

### Distribution

OpenVINO provides different types of builds:
- Regular releases  
- Long-Term Support (LTS)  
- Pre-release versions  
- Nightly builds
